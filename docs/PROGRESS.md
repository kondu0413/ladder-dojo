### 分かったこと(改善 7)
- **メールは 0円では送れない。壁は送信サービスではなく送信元ドメイン**。`workers.dev` のサブドメインには SPF / DKIM の DNS レコードを置けないので、`@ladder-dojo.mojya.workers.dev` から送ることはできない(Cloudflare 自身のドキュメントに明記)
- 2024 年 2 月以降、Gmail / Yahoo / Microsoft が送信ドメインの認証を必須にした。**認証が無いと Brevo は差出人を `@brevosend.com` に書き換える**。届きはするが誰からのメールか分からず、製品の通知としては使えない。**D-008 の「Brevo は独自ドメイン不要」は、もう成り立たない**
- MailChannels の Workers 向け無料枠は **2024 年に終了済み**(D-008 を書いた当時の前提)
- Cloudflare 自身の Email Sending は 2026-04 に public beta。**Workers Paid($5/月)必須で無料枠なし**
- Resend の無料枠は 3,000通/月・100通/日・検証済みドメイン 1 つ。**ドメインさえあれば送信サービスは 0円で足りる**

### 見つけたこと(改善 7)
- **メールを使わなければ、通知は 0円で実装できる**。Web Push(RFC 8291)は Workers の Web Crypto + VAPID で完結し、外部サービスが要らない。すでに PWA と Service Worker がある(S-013)ので土台は揃っている。VAPID 鍵は `BETTER_AUTH_SECRET` と同じく CI に生成させれば、**Claude Code が秘密の鍵に触れない**運用ルールも守れる(GitHub Secrets は 3 つのまま)
- **ただしメールの代わりにはならない**。Web Push は**アプリを一度も開いていない人には届かない**し、iOS ではホーム画面に追加していないと受け取れない。「全員に確実に知らせる」が要るならメール(= ドメイン)が要る
- どちらを先に作るかは**人間の判断待ち**にした(下の「人間への依頼」)。当初の「メールで知らせる」とは別物になるため

### 2026-09-16 の作業(改善 12: 投稿問題の検索を FTS5 に)
これまでの検索は `instr()` の全表走査だった。投稿が増えると 1 回の検索で全行を読むので、D1 の読み取り行数に効いてくる(COST.md §1.2)。

**素直に FTS5 に置き換えると日本語の検索は今より悪くなる**ことが、下調べで分かった。ローカルの D1 で実測すると、trigram トークナイザは「自己保持」「タイマ」「リセット」には当たるのに、**「保持」「値」では 0 件**になる。3 文字未満に当たらないためで、日本語では 2 文字の語(保持・接点・出力・解除)がごく普通に出てくる。
